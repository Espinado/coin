## 1. Что мы строим

**Coin** — веб-платформа «AI Compute». Человек без покупки железа «арендует» вычислительную мощность (TFLOPS) из дата-центров, получает за это награды в токене **COIN** и управляет всем через личный кабинет.

Это не биржа и не классический майнинг-пул. Это **сервис с простым циклом:**

> зарегистрировался → выбрал тариф → получаешь COIN → выводишь на кошелёк → приглашаешь друзей

Параллельно есть **админ-панель**, где оператор платформы управляет тарифами, начислениями, выводами, пользователями и поддержкой.

---

## 2. Зачем это нужно

### Пользователю

- Не нужно покупать и обслуживать оборудование
- Всё в одном месте: тариф, контракт, баланс, история, вывод
- Живая поддержка в чате (можно написать ещё до регистрации)
- Реферальная ссылка — бонус за приглашённых

### Владельцу платформы

- Единый продукт для привлечения и удержания аудитории
- Рефералка как канал роста
- Админка для ежедневной операционной работы без правок в коде
- Настраиваемые параметры: ставка награды, комиссии, % рефералки, KYC

---

## 3. Как это работает (логика продукта)

```
Тариф (Plan)
    ↓ пользователь покупает
Контракт (Contract) — активная «мощность» на срок
    ↓ каждую эпоху (Epoch)
Начисление COIN на кошелёк (Wallet)
    ↓ пользователь накопил достаточно
Заявка на вывод (Withdrawal) → админ обрабатывает → COIN уходит на payout address

Параллельно:
Реферальная ссылка → друг регистрируется → пригласивший видит +1 invited и получает % с наград
```

**Эпоха (epoch)** — период расчёта. Награда за эпоху ≈ `TFLOPS × ставка × multiplier тарифа`.  
Ставка и частота эпох задаются в настройках платформы.

**KYC** — статус пользователя (none / pending / approved / rejected). Может быть обязательным для вывода.

## 4. Путь пользователя (User Journey)

### 4.1. Новый пользователь

1. Заходит на **лендинг** `coin.arguss.lv` — узнаёт о продукте, смотрит тарифы
2. Может написать в **чат поддержки** без регистрации (указав email)
3. Нажимает **Register** (или переходит по реферальной ссылке `/r/COIN-XXXXX`)
4. Регистрируется → попадает в **Dashboard**

### 4.2. Основной сценарий (целевой)

5. Открывает секцию **Plans** → выбирает тариф → **покупает** (создаётся контракт)
6. В **Overview / Contracts** видит активный контракт и прогресс
7. Каждую эпоху на **Wallet** приходят начисления COIN
8. В **Statistics** смотрит динамику (день / неделя / месяц)
9. В **Settings** указывает payout address
10. В **Wallet** подаёт **заявку на вывод**
11. После одобрения админом — COIN отправлен на указанный адрес

### 4.3. Реферальный сценарий

1. Пользователь в **Referrals** копирует свою ссылку (`/r/COIN-XXXXX`)
2. Друг переходит по ссылке → регистрируется
3. Пригласивший видит **Invited +1**, **Level 1 users +1**
4. *(Целевое состояние)* пригласивший получает **% от наград** приглашённого, пока у того активен контракт

### 4.4. Поддержка

- **Guest** (на лендинге): создаёт тикет с email, переписывается в realtime
- **User** (в dashboard): создаёт тикет, получает ответы мгновенно через WebSocket
- **Admin**: видит все тикеты, отвечает, меняет статус

## 5. Роли

| Роль | Где работает | Что делает |
|------|--------------|------------|
| **Guest** | Лендинг | Читает, пишет в поддержку |
| **User** | `coin.arguss.lv` | Dashboard: тарифы, контракты, кошелёк, рефералка, настройки, support |
| **Admin** | `admin.coin.arguss.lv` | Пользователи, тарифы, эпохи, выводы, настройки, support |

User и Admin — **разные домены и разные сессии**. Cookies между ними не пересекаются.

## 8. Что уже сделано

### Работает по-настоящему

- **Лендинг** — маркетинговая страница с секциями Product, Plans, FAQ и т.д.
- **Регистрация / login / профиль** — Laravel Breeze, кастомный UI
- **Dashboard UI** — все 8 секций, мобильное меню
- **Admin panel** — все модули, отдельный домен
- **Support chat** — user + guest + admin, realtime через Reverb (WebSocket)
- **Referral Level 1** — ссылка `/r/{code}` → cookie → регистрация → +1 invited у пригласившего
- **Epoch settlement** — логика начислений на wallet (запуск вручную из админки или artisan)
- **Withdrawal workflow** — admin меняет статусы, баланс hold/release, запись в wallet transactions
- **Platform settings** — reward rate, fees, referral %, KYC flag (через admin)
- **Deploy** — скрипт на prod, миграции, Reverb watchdog

### Работает частично / только в demo

- **Dashboard цифры** у demo-пользователя (`test@test.lv`) — из seeder, не из реальных действий
- **Referral accruals** в UI — демо-строки, автоматического начисления % нет
- **Кнопка withdrawal** в Wallet — есть в UI, но не отправляет заявку
- **Кнопка «Activate compute»** на лендинге — декоративная
- **Level 2 рефералка** — поля в UI, логики нет (и не планируется на текущем этапе)

### Не сделано

- Покупка тарифа пользователем (создание контракта)
- Подача заявки на вывод пользователем
- Автоматический запуск epochs по cron
- Начисление реферальных % с наград приглашённых
- KYC: загрузка документов
- Депозит / пополнение / интеграция с блокчейном
- Maintenance mode (настройка есть, проверки нет)
- PWA, мультиязычность

## 9. Что получим в итоге (целевой продукт)

### Для пользователя

Полный цикл без участия разработчика:

1. Зашёл на сайт → зарегистрировался (в т.ч. по реф. ссылке)
2. Выбрал тариф → контракт активен
3. COIN начисляются автоматически каждую эпоху
4. Видит баланс, историю, статистику
5. Подал заявку на вывод → получил COIN на свой адрес
6. Пригласил друга → видит статистику и реферальные начисления

### Для админа

1. Управляет тарифами и настройками платформы
2. Видит пользователей, блокирует, меняет KYC
3. Запускает / автоматизирует epochs
4. Обрабатывает выводы
5. Отвечает в support в realtime

### Технически

- Стабильный prod на `coin.arguss.lv` + `admin.coin.arguss.lv`
- Reverb работает 24/7 (watchdog + cron)
- Без demo-данных для основного user flow

## 10. Definition of Done — когда продукт «готов»

Продукт считаем **готовым к запуску для реальных пользователей**, когда выполнены все пункты:

### Must have (обязательно)

- [ ] **Покупка тарифа** — user выбирает plan → создаётся contract → wallet/TFLOPS обновляются
- [ ] **Авто-epochs** — cron запускает settlement без ручного вмешательства
- [ ] **User withdrawal** — user подаёт заявку → admin обрабатывает → баланс корректен
- [ ] **Referral L1 accrual** — % от наград приглашённого начисляется пригласившему
- [ ] **End-to-end тест** — новый user проходит полный цикл без seeder/demo

### Should have (желательно)

- [ ] KYC submission flow (хотя бы заявка + admin approve)
- [ ] Maintenance mode реально блокирует user-доступ
- [ ] Email-уведомления (регистрация, withdrawal status, support reply)

### Out of scope (не в текущем этапе)

- Referral Level 2
- Реальная on-chain интеграция (депозит/вывод в блокчейне)
- PWA
- Мультиязычность

## 11. Приоритетный backlog

| # | Задача | Зачем |
|---|--------|-------|
| 1 | **Plan purchase → contract** | Без этого нет продукта — user не может «активировать compute» |
| 2 | **Cron epochs** | Награды должны капать сами |
| 3 | **User withdrawal request** | User должен сам вывести, не через admin вручную |
| 4 | **Referral commission (L1)** | Рефералка без % — только счётчик, не мотивация |
| 5 | KYC flow | Если выводы реальные — нужна верификация |
| 6 | Maintenance mode | Перед апдейтами / инцидентами |
